# Host Integrator Guide

This guide explains how to integrate SAK into a mobile application and build a dynamic UI shell.

---

## 1. Initializing the Runtime
The host is responsible for bootstrapping the SAK runtime during app startup.

### Setting up the Launcher
```kotlin
val scope = rememberCoroutineScope() // Or a GlobalScope/ProcessScope
val launcher = SakLauncher(scope)

val runtime = launcher.launch(
    defaultConfig = myAppConfig,
    featureModules = discoverFeatureModules(),
    deps = SakDependencies(licenseProvider = myLicenseProvider)
)
```

### Dependency Discovery
- On Android, `discoverFeatureModules()` uses the `ServiceLoader`.
- On iOS, it uses the registry generated by the KSP processor.

---

## 2. Building the UI Shell
The host owns the navigation structure. Use `SakFeaturePlaceHolder` to define where features can inject their UI.

### Compose Example (Android)
```kotlin
@Composable
fun MainApp(runtime: SakRuntime) {
    Scaffold(
        bottomBar = { MyBottomNav() }
    ) { padding ->
        NavHost(...) {
            composable("home") {
                // SAK finds all features with category="home" and renders their widgets
                SakFeaturePlaceHolder(
                    runtime = runtime,
                    category = "home",
                    onNavigate = { route -> navController.navigate(route.value) }
                )
            }
        }
    }
}
```

---

## 3. Customizing Widgets
While SAK provides a standard `SakEntryWidget` that handles data-driven fallbacks, you can override how widgets are rendered globally or per-category.

### Data-Driven UI
If a feature does *not* provide a custom Composable, SAK renders a generic widget based on the `EntryPoint` metadata:
- `title`: From `id` (slugified).
- `icon`: Provided in `metadata`.
- `action`: Handled by the host's `onNavigate` callback.

---

## 4. Handling Errors
Features run in a "Sandbox." If a feature fails to load or its UI crashes:
1.  The runtime marks it as `FeatureState.Error`.
2.  `SakFeaturePlaceHolder` will automatically render a `SakErrorWidget` for that feature.
3.  The rest of your app remains perfectly functional.

---

## 5. Integrating with iOS
On iOS, the `SakIosHost` class provides a "Headless" bridge for native SwiftUI development.

```swift
let host = SakIosHost()

// Subscribe to config changes to re-draw your TabView
host.setConfigListener { config in
    self.tabs = config.features.filter { $0.isVisible }
}

// Query widgets for a specific screen
let entries = host.entriesForCategory(category: "home")
```

For a full native experience, you should build your own SwiftUI cards that map to the metadata provided in `IosResolvedEntry`.
